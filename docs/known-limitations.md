# Known Limitations

- 対応対象は YMM4 プロジェクト JSON 内の `FilePath` です。
- PSD の `EnableLayers` または `EnableLayerPaths` がある場合、`EnableLayersFilePath` は `FilePath` と同じリソース参照として同梱・展開時に同期します。同一性は相対 path などを解決した後の resource path で判定します。欠落値はこの条件でのみ生成し、別の PSD を指す既存値は上書きしません。
- VideoItem の連番 PNG は、実在し、除外されていない代表画像を起点に、同じフォルダで接頭辞・末尾数値・`.png` 拡張子が一致する実在ファイルを収集します。兄弟画像の除外指定も有効です。数値の欠番や桁数の違いはグループを分割しません。同じ命名規則の別用途画像も候補になります。YMM4側の判定やPNG以外の連番形式は未検証です。
- UI設定を除外した場合、ルートの `ToolStates` と `LayoutXml` にしか現れない参照は格納対象から外れます。他の箇所からも参照する素材は同梱できます。
- 未知の YMM4 内部形式は完全には保証しません。
- YMM4 DLL はリポジトリに同梱しません。
- 複数の `YmmpxLib.dll` を同時配置する運用は非推奨です。
- アーカイブは最大 10,000 エントリ、単一素材 50 GiB、合計展開サイズ 100 GiB に制限されます。プロジェクトは 512 MiB、リンク定義は 64 MiB、プロジェクトマーカーは 16 KiB が上限です。
- 展開サイズが 100 MiB を超えるエントリおよびアーカイブ全体には、最大 1,000 倍の圧縮率制限が適用されます。
- 作成したパッケージが圧縮率制限を超える場合は、展開互換性を保つため自動的に無圧縮で再構築されます。

## 参照と原本の保全

- 新規作成時、欠損・除外で残るプロジェクト内の参照や PSD の補助参照と、同梱素材の格納パスが衝突しないよう割り当てます。旧アーカイブですでに異なる参照が同じ文字列に変わっている場合、その文字列だけから元の意図を判別できません。元プロジェクトを参照して再作成する必要があります。
- 出力先が入力プロジェクトや検出できた素材と同じ実体を指す場合は作成を拒否します。除外した入力も保護対象です。開始時から同じ実体を確認できる無関係な既存出力は、従来どおり上書きできます。
- 既存出力の上書きには、OSとファイルシステムで実体IDを確認できることが必要です。新規出力は上書きなしで確定します。既存出力の最後の照合と置換は不可分の操作ではないため、その間の変更や、既存出力の同一実体に対する並行書き込みは検出できない場合があります。

## 新旧リンク定義が混在するパッケージ

- 展開時は `links.json`、`manifest.json`、`links.txt` の順に調べます。宛先を解決できる項目がある最初の形式を優先します。同じ形式で一つの参照キーに異なる実在宛先がある場合は、そのキーを未解決にします。
- 下位の定義は、優先形式にキーの宣言がなく、今回展開した `resources/` 内の同じ相対パスを指し、定義間で競合がない場合に限り補完します。優先形式に宛先が欠損した宣言があるキーや、任意の旧パスからの付け替えは補完しません。採用できたリンクは `LinkMap` に入り、補完を見送ったキーの件数は診断トレースで確認できます。
- 単独の `LoadLinkMap(string)` 呼び出しでは、展開したエントリの一覧がないため、下位定義の補完を行いません。旧形式だけのパッケージは従来の順序で読み込みます。
